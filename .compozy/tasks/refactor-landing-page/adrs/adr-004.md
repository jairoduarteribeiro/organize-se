# ADR-004: Replace pulse-glow with scale-pulse animation on checkout buttons

## Status

Accepted

## Date

2026-05-20

## Context

PRD F5 requires checkout buttons to animate with a `scale` grow/shrink cycle (~103%) to draw attention. The existing `pulse-glow` keyframe in `globals.css` already includes `transform: scale(1.015)` alongside `box-shadow`, but at a very subtle level. Two approaches were available: modify the existing keyframe or define a new one.

## Decision

Define a new `@keyframes scale-pulse` in `globals.css` that scales `1.0 → 1.03 → 1.0` with no `box-shadow`. Replace the `animate-pulse-glow` utility class on checkout buttons with a new `animate-scale-pulse` utility. The original `pulse-glow` keyframe is removed.

## Alternatives Considered

### Alternative 1: Extend pulse-glow in place

- **Description**: Increase the scale value in the existing `pulse-glow` keyframe from `1.015` to `1.03` and remove the `box-shadow` lines.
- **Pros**: One fewer keyframe name; no class rename required.
- **Cons**: The animation name (`pulse-glow`) no longer describes the visual behavior (no glow); misleading to future developers.
- **Why rejected**: Semantic clarity: a keyframe named `pulse-glow` that applies only scale is confusing.

### Alternative 2: Run both animations in parallel

- **Description**: Keep `animate-pulse-glow` and add a second animation utility for scale only, applying both to the button.
- **Pros**: Additive approach; no removal of existing behavior.
- **Cons**: Two simultaneous `transform` animations conflict unless composed carefully; increases CSS specificity risk.
- **Why rejected**: Transform conflicts make this fragile; not needed since the PRD says to replace the existing animation.

## Consequences

### Positive

- Single `transform: scale()` call per keyframe — GPU-composited, no layout shift.
- Animation name accurately describes the visual behavior.
- On hover, `transform: scale()` from the animation is overridden naturally by the hover state.

### Negative

- Any future usage of `animate-pulse-glow` (if any) must be updated. Codebase search confirms it is used only in `CTABlock.tsx`.

### Risks

- `prefers-reduced-motion` in `globals.css` already disables all animations — no additional handling needed.

## Implementation Notes

```css
/* globals.css */
@keyframes scale-pulse {
  0%, 100% { transform: scale(1); }
  50%       { transform: scale(1.03); }
}

@theme inline {
  --animate-scale-pulse: scale-pulse 2s ease-in-out infinite;
}
```

Button class change in `CTABlock.tsx`:
```diff
- className="... animate-pulse-glow ..."
+ className="... animate-scale-pulse hover:animate-none ..."
```
