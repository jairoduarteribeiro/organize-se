# ADR-005: DOM reorder to fix mobile hero title visibility

## Status

Accepted

## Date

2026-05-20

## Context

PRD F6 reports that on mobile (< 768px) the hero image stacks above the heading text, hiding "Workshop ORGANIZE-$E" from mobile visitors. The current `HeroSection.tsx` renders the heading block after the image block in DOM order. Three layout strategies were available: reorder the DOM, use CSS positioning, or duplicate the node.

## Decision

Move the heading/subheading JSX above the `<Image>` block in `HeroSection.tsx`. On desktop (`md:` and above), restore the original visual order using `flex-col-reverse` or a named grid area so the image appears first visually. This keeps a single DOM node for the heading and avoids z-index stacking.

## Alternatives Considered

### Alternative 1: CSS z-index + absolute positioning

- **Description**: Keep DOM order unchanged. Add `relative`/`absolute` positioning to overlay the heading on top of the image at mobile sizes.
- **Pros**: No DOM structure change; original code remains mostly intact.
- **Cons**: Requires explicit height management on the image container; risks clipping or overflow on devices where the image height varies. Conflicts possible with the existing 3-variant responsive image carousel.
- **Why rejected**: The responsive image carousel already manages height via `42vh` on mobile; adding absolute overlays introduces fragile coupling.

### Alternative 2: Conditional rendering (duplicate node)

- **Description**: Render the heading block twice — once above the image (visible only on mobile) and once in its current position (visible only on desktop).
- **Pros**: Zero layout risk.
- **Cons**: Two DOM nodes for the same semantic content; screen readers encounter the heading twice; duplicated JSX that must be kept in sync.
- **Why rejected**: Semantically incorrect; accessibility issue; maintenance burden.

## Consequences

### Positive

- Single heading node in DOM — correct for accessibility and SEO.
- No z-index or height management needed.
- Visual order on desktop preserved via CSS, not duplicated markup.

### Negative

- DOM order differs from visual order on desktop — developers must be aware that `flex-col-reverse` or `order-` classes control visual sequencing.

### Risks

- If desktop layout relies on sibling selectors targeting the heading immediately after the image, those selectors may need updating. Current codebase does not use such selectors.

## Implementation Notes

Simplified structure in `HeroSection.tsx`:

```tsx
// Mobile: title appears first in flow (natural DOM order)
// Desktop (md:): flex-col-reverse restores image-first visual order
<section className="flex flex-col md:flex-col-reverse ...">
  <div className="heading-block"> {/* appears first on mobile */}
    <h1>Workshop ORGANIZE-$E</h1>
    ...
  </div>
  <div className="image-block"> {/* appears below heading on mobile */}
    <Image ... />
  </div>
</section>
```
