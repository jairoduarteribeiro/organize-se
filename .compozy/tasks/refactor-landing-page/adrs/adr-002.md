# ADR-002: next/font/google for Bebas Neue and Inter loading

## Status

Accepted

## Date

2026-05-20

## Context

The PRD (F2) requires loading Bebas Neue (display headings) and Inter (body copy) into the landing page. Two options exist: use the Google Fonts CDN via `<link>` tags in the document `<head>`, or use Next.js's built-in `next/font/google` API which self-hosts fonts at build time. ADR-001 listed the Google Fonts CDN as a mitigation risk due to potential regional blocking. The project already runs on Next.js 16, which fully supports `next/font/google`.

## Decision

Load Bebas Neue and Inter using `next/font/google` in `app/layout.tsx`. Expose each font as a CSS variable (`--font-display` for Bebas Neue, `--font-body` for Inter) and register them in `globals.css` under `@theme inline`.

## Alternatives Considered

### Alternative 1: Google Fonts `<link>` tags

- **Description**: Add `<link rel="preconnect">` and `<link href="https://fonts.googleapis.com/...">` in `layout.tsx`'s `<head>` using `next/head` or the metadata API.
- **Pros**: Exactly matches PRD literal wording; zero API learning curve.
- **Cons**: Adds a CDN network round-trip on every page load; potential render-blocking on slow connections; regional CDN availability risk noted in ADR-001.
- **Why rejected**: `next/font/google` is strictly superior for this stack — same visual result, better performance, no CDN dependency.

## Consequences

### Positive

- Fonts are self-hosted at build time — no CDN round-trip, no render-blocking request.
- `font-display: swap` is applied automatically by `next/font`.
- CSS variables (`--font-display`, `--font-body`) can be consumed by Tailwind `@theme` and applied anywhere in the component tree.
- No change to the CDN-blocking risk noted in ADR-001 (risk is eliminated, not mitigated).

### Negative

- Slight divergence from the PRD's literal `<link>` wording — justified by the superior technical outcome.

### Risks

- Bebas Neue has limited character coverage (uppercase Latin only). Any heading that contains mixed-case or non-Latin text must fall back to Inter.

## Implementation Notes

```ts
// app/layout.tsx
import { Bebas_Neue, Inter } from "next/font/google";

const bebasNeue = Bebas_Neue({
  weight: "400",
  subsets: ["latin"],
  variable: "--font-display",
  display: "swap",
});

const inter = Inter({
  subsets: ["latin"],
  variable: "--font-body",
  display: "swap",
});
```

In `globals.css`:
```css
@theme inline {
  --font-sans: var(--font-body), Arial, sans-serif;
  --font-display: var(--font-display), Arial, sans-serif;
}
```
