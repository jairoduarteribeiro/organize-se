# ADR-001: Layered-by-concern implementation strategy for landing page refactor

## Status

Accepted

## Date

2026-05-20

## Context

The ORGANIZE-$E workshop landing page requires 8 distinct changes spanning typography, layout, component design, interaction animations, and mobile responsiveness. Each change touches different files and concerns. The team needed to decide how to organize the implementation work to maximize traceability and minimize the risk of regressions.

## Decision

Implement all changes grouped into 5 independent concern layers, applied sequentially:

1. **Typography** — Switch system fonts to Bebas Neue (headings) + Inter (body) via Google Fonts
2. **Layout** — Center the CTABlock (countdown + checkout button) below the qualifying copy in PainQualifier
3. **Components** — Redesign GuaranteeSeal into a circular stamp badge (yellow) and add B&W Instagram icon to BioSection
4. **Animations** — Replace or augment the existing pulse-glow on checkout buttons with a scale grow/shrink animation
5. **Mobile** — Fix hero section title visibility overlap and countdown "segundos" label overflow on small screens

## Alternatives Considered

### Alternative 1: All-in-one pass

- **Description**: Implement all 8 changes in a single file-by-file pass
- **Pros**: Fastest to ship, single PR, no intermediate states
- **Cons**: Harder to trace regressions; a bug in animations could mask a mobile fix
- **Why rejected**: Risk of interleaved regressions outweighs the speed gain for a visual-heavy change set

### Alternative 2: Impact-first priority

- **Description**: Fix mobile bugs first, then apply design changes, then animations
- **Pros**: Ships the most critical UX fix immediately
- **Cons**: Typography changes applied twice if the hero section is also touched during mobile fix; double-pass increases churn
- **Why rejected**: The mobile typography fix and the global typography change overlap, causing redundant work

## Consequences

### Positive

- Each layer produces a clean, reviewable diff scoped to one concern
- Playwright tests can be run after each layer to catch regressions early
- Typography layer unblocks all other visual layers since font context must be established first

### Negative

- Slightly more implementation steps than a single pass
- Developer must context-switch between layers rather than working file by file

### Risks

- Google Fonts CDN dependency adds a network round-trip; mitigated by using `display=swap` and `font-display: swap`
- Bebas Neue does not support lowercase glyphs — all headings using this font must be uppercase or use Inter as fallback

## Implementation Notes

- Load Google Fonts in `app/layout.tsx` via `<link>` tags in `<head>` using Next.js font optimization
- Apply Bebas Neue via a CSS custom property (`--font-display`) and Inter via `--font-body`
- The circular seal is a pure CSS/SVG approach — no new icon library dependency required
- The Instagram icon should use the existing Lucide React package (already a dependency) if available, otherwise inline SVG
