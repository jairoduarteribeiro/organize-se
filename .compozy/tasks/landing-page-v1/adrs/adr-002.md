# ADR-002: Client-Side Countdown Timer for Post-Event State Detection

## Status

Accepted

## Date

2026-05-19

## Context

The landing page must display a live countdown to June 28, 2026 10:00 BRT and automatically switch to waitlist mode once the event has passed. Three mechanisms were evaluated: client-side date check, a build-time env flag, and a server-side date check in the App Router page component.

## Decision

Use a client-side `CountdownTimer` component that calculates remaining time from a fixed UTC timestamp (`2026-06-28T13:00:00Z`) on every render tick. When the timer reaches zero, the component emits an `isExpired` flag up to the page, which toggles CTA buttons to the waitlist form. No rebuild or redeploy is required for the post-event transition.

## Alternatives Considered

### Alternative B: Build-Time Env Flag

- **Description**: Set `NEXT_PUBLIC_EVENT_ENDED=true` in Vercel and redeploy after the event
- **Pros**: Zero client JS dependency; dead simple
- **Cons**: Requires a manual Vercel action on event day — risk of forgetting or being unavailable
- **Why rejected**: Human-gated deployment introduces unnecessary operational risk on a specific date

### Alternative C: Server-Side Date Check

- **Description**: `app/page.tsx` reads `new Date()` at request time; returns different JSX when event is past
- **Pros**: No client JS; automatic
- **Cons**: Requires Vercel Edge Runtime or ISR revalidation to stay current without full rebuild; adds server infrastructure complexity for a simple date comparison
- **Why rejected**: Adds infrastructure scope for a problem the client-side approach solves adequately with zero new dependencies

## Consequences

### Positive

- Automatic post-event switch at the exact UTC timestamp, no human action required
- CountdownTimer is a self-contained `"use client"` component; the rest of the page remains a Server Component
- Timer can be tested by mocking `Date.now()` in unit tests

### Negative

- Timer re-renders every second, adding minor CPU overhead on mobile
- Client JS must load before the correct CTA state is shown (tiny flash risk on very slow connections)

### Risks

- Visitors with wrong device clocks may see incorrect state — mitigated by anchoring to UTC, not local time
- Timer must be cancelled on unmount to avoid memory leaks — handled by `useEffect` cleanup

## Implementation Notes

- Event timestamp constant: `EVENT_UTC = new Date('2026-06-28T13:00:00Z')` (June 28 10:00 BRT = UTC-3)
- `useCountdown(target: Date)` hook returns `{ days, hours, minutes, seconds, isExpired }`
- Timer interval is cleared in the `useEffect` return function
- When `isExpired === true`: hide countdown, replace CTA buttons with `<WaitlistForm />`
