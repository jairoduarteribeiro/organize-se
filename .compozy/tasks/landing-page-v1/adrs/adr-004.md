# ADR-004: CSS Keyframes + IntersectionObserver for Scroll Animations

## Status

Accepted

## Date

2026-05-19

## Context

The PRD requires scroll-triggered animations (section fade-in, checklist stagger-reveal, CTA pulse) that respect `prefers-reduced-motion`. Three approaches were evaluated: a custom CSS + IntersectionObserver solution, Framer Motion, and CSS scroll-driven animations.

## Decision

Implement a `useInView` custom hook wrapping the browser's `IntersectionObserver` API. The hook adds/removes a CSS class (`is-visible`) on the observed element. CSS handles the actual animation via `@keyframes` and `transition`. CTA pulse uses a standalone `@keyframes` animation applied via Tailwind's arbitrary `animate-` utilities. All animations are suppressed with `@media (prefers-reduced-motion: reduce)`.

## Alternatives Considered

### Alternative B: Framer Motion

- **Description**: Add `framer-motion` package; use `<motion.div>` with `whileInView` and `viewport` props
- **Pros**: Declarative; composable; rich spring physics
- **Cons**: ~40 KB bundle addition; heavier for what is essentially 3 animation patterns; not justified by the scope
- **Why rejected**: Bundle cost is disproportionate to the animation complexity; zero-dependency approach covers all required patterns

### Alternative C: CSS Scroll-Driven Animations

- **Description**: Use `animation-timeline: scroll()` (CSS-only, no JS)
- **Pros**: No JS; silky performance via compositor thread
- **Cons**: Limited mobile browser support (not available on iOS Safari < 18); animations tied to scroll position rather than entry visibility
- **Why rejected**: Target audience is mobile-first; iOS Safari incompatibility is a critical blocker

## Consequences

### Positive

- Zero new dependencies
- IntersectionObserver is widely supported on all target browsers
- CSS handles rendering; JS only toggles a class
- `prefers-reduced-motion` compliance is a single CSS media query

### Negative

- IntersectionObserver is not available in SSR; `useInView` must guard against `typeof window === 'undefined'`
- Stagger delays for checklist items must be applied via inline `style={{ animationDelay }}` or Tailwind `delay-` variants

### Risks

- IntersectionObserver root margin must be tuned to trigger animations before elements are fully in viewport — mitigated by defaulting to `rootMargin: '0px 0px -50px 0px'`

## Implementation Notes

- `useInView(ref, { threshold: 0.15 })` — returns `inView: boolean`
- Base class: `opacity-0 translate-y-4 transition-all duration-500`
- Visible class: `opacity-100 translate-y-0`
- CTA pulse: `@keyframes pulse-glow` added to `globals.css`; applied via `animate-pulse-glow` in Tailwind
