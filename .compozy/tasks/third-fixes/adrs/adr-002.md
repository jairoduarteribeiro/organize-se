# ADR-002: Portuguese Locale for html lang Attribute

## Status

Accepted

## Date

2026-05-21

## Context

The hydration error trace showed the server rendering `lang="pt-PT"` while `app/layout.tsx` declared `lang="en"`, causing a React hydration mismatch. Fixing the mismatch requires picking a single Portuguese locale that both server and client emit. Three options exist: `pt-PT` (European Portuguese, matching the server trace), `pt-BR` (Brazilian Portuguese, matching the workshop's target audience), and `pt` (generic, no region variant).

## Decision

Use `lang="pt-BR"`. The workshop's primary audience is Brazilian women; `pt-BR` is the semantically accurate locale for the page's content and target market.

## Alternatives Considered

### Alternative A: pt-PT

- **Description**: European Portuguese — matches what the server trace was emitting before the hydration mismatch existed
- **Pros**: Requires no explanation as to why the locale differs from the server trace; Rafaela lives in Portugal
- **Cons**: Wrong semantic choice for a page whose content, pricing, and scheduling all target Brazilian users (BRT timezone, BRL currency implied, Brazilian idioms)
- **Why rejected**: Locale accuracy for the audience outweighs matching an accidental server-side value

### Alternative B: pt (generic)

- **Description**: Language tag without a region subtag
- **Pros**: Avoids the pt-PT vs pt-BR debate entirely; valid BCP 47
- **Cons**: Browsers may apply either locale's hyphenation, spellcheck, and number formatting inconsistently; less precise
- **Why rejected**: Region specificity is available and meaningful here; generic `pt` provides no advantage

## Consequences

### Positive

- Hydration mismatch is eliminated: both server and client emit `lang="pt-BR"`
- Browser spellcheck and hyphenation apply Brazilian Portuguese rules, consistent with the page content
- Screen readers announce the language correctly for the target audience

### Negative

- Rafaela is based in Portugal; `pt-BR` subtly misrepresents the instructor's locale, though this has no user-visible effect

### Risks

- None identified; changing the `lang` attribute has no effect on JavaScript execution or layout
