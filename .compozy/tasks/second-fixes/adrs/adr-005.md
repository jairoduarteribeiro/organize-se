# ADR-005: Instagram Icon Gradient Technique

- **Status**: Accepted — supersedes ADR-003
- **Date**: 2026-05-21

## Context

ADR-003 committed to applying the Instagram brand gradient to the `BioSection` icon but left the implementation open between two mechanisms: (a) a CSS `background-clip`/gradient-mask on the Lucide SVG wrapper, or (b) an inline `<svg>` with a `<linearGradient>` definition in `<defs>`. This ADR narrows that choice to a single implementation.

## Decision

Replace the `createLucideIcon`-based Instagram component with a hand-authored **inline `<svg>` containing a `<linearGradient>` in `<defs>`** and `stroke="url(#ig-gradient)"` on all paths.

## Alternatives Considered

| Approach | Trade-offs |
|----------|-----------|
| **CSS gradient mask** (`background: linear-gradient; background-clip: text; -webkit-text-fill-color: transparent`) | Works for text nodes; applying it to SVG `fill`/`stroke` attributes is unreliable across browsers — Safari and Firefox may ignore the clip on SVG child elements |
| **Flat brand purple `#833AB4`** | Zero implementation complexity; rejected because the requirement explicitly calls for the official two-color gradient |

## Consequences

- `createLucideIcon` import is removed from `BioSection.tsx`; resolves the F1 key-prop warning as a side-effect (Lucide's internal path-array rendering is eliminated).
- The inline SVG uses the same path data as the Lucide Instagram icon — no visual difference except the gradient.
- Gradient `id="ig-gradient"` is scoped to the single SVG element; no page-level ID collision because the icon appears exactly once in the DOM.
- Safari renders SVG `stroke/fill` with `url(#gradient)` correctly when the `<defs>` block is a sibling within the same `<svg>`.
