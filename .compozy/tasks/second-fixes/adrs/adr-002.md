# ADR-002: Delivery Scope — Single PR

- **Status**: Accepted
- **Date**: 2026-05-21

## Context

The second-fixes batch contains 10 distinct improvements spanning bug fixes, copy changes, image swaps, and interactive feature additions. The question is whether to deliver them as one PR or split them.

## Decision

Deliver all 10 changes in a **single PR**.

## Alternatives Considered

| Approach | Trade-offs |
|----------|-----------|
| **Two PRs** (interactive first, then visual) | Reduces JS risk isolation but adds review overhead and slows delivery for a UI-only batch |
| **Three PRs** (bugs / interactive / polish) | Maximum isolation at the cost of significant PR management overhead; changes are small enough that a single review is lower-risk than three merge windows |

## Consequences

- All changes are UI-only with no backend surface; blast radius is contained.
- Single review pass and single deploy cycle.
- End-to-end Playwright test covers the full batch in one run.
