# ADR-004: Testimonials Component File Strategy

- **Status**: Accepted
- **Date**: 2026-05-21

## Context

The testimonials carousel (F7) requires replacing the static grid in `Testimonials.tsx` with an Embla Carousel instance. Two options exist: rewrite the file in-place or create a new `TestimonialsCarousel.tsx` component and import it from the existing file (or from `page.tsx`).

## Decision

Rewrite **`Testimonials.tsx` in-place**. The exported function name and public API stay the same; only the internal rendering logic changes.

## Alternatives Considered

| Approach | Trade-offs |
|----------|-----------|
| **New file `TestimonialsCarousel.tsx`** | Clean separation between old and new, but requires updating `page.tsx` (or `Testimonials.tsx`) imports — extra churn with no benefit for a one-file swap |
| **Wrapper approach** | Wrap the existing grid in an Embla container without touching the grid markup — creates a hybrid DOM structure that conflicts with carousel slide alignment requirements |

## Consequences

- `page.tsx` import (`Testimonials`) remains unchanged.
- The static grid markup and `useInView` scroll-animation are replaced entirely; neither is needed once Embla handles the slide container.
- Embla's `"use client"` requirement aligns with the existing `"use client"` directive already present in `Testimonials.tsx`.
